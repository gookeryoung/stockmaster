## 1. 背景与设计目标

### 1.1 产品现状

StockMaster 是单机可部署的 A 股日线量化研究工作台，闭环是
**数据 → 指标/因子 → 预测 → 预警 → 回测**。后端能力（账号、工作区、预警、回测、备份）
已经完整，但界面上有三处“功能已到、入口未到”的落差：

1. **账号**：登录与注册挤在同一张卡片里用 Tab 切换，错误提示直接展示后端 `detail`；
   首次部署（首个账号自动成为管理员）、强制登录关闭、微信 mock 三种情形只靠零散提示；
   账号设置页信息密度高但与“我的数据”混排。
2. **工作区**：`frontend/src/pages/Workspace.tsx` 已 1100+ 行，成员、通道、模板、用量、
   趋势、策略、管理员总览全部竖向堆叠；owner 与 viewer 看到的是同一张长页，只是按钮隐显，
   高风险操作（转让、删除、清空）缺少统一确认模式。
3. **自选**：只有 `Market` 页的“加入自选”和 `Dashboard` 的一张只读卡片，没有独立管理页；
   后端 `GET/POST/DELETE /watchlist` 的能力（多清单、备注、幂等更新）大部分没有入口，
   “选股 → 观察 → 预警”的链路在最后一步断掉。

目标信息架构的文字版见 §4。

### 1.2 三个设计对象

| 对象 | 核心问题 | 成功标准 |
|---|---|---|
| 账号 | “我是谁、我能不能进来、进来后怎么管自己” | 首次访问 30 秒内完成登录或注册；失败能看懂原因并知道下一步 |
| 工作区 | “我和谁共享数据、我的权限边界在哪” | 角色差异一眼可见；危险操作可逆/需确认；owner 5 分钟内完成成员与通知配置 |
| 自选 | “我关注什么、怎么把这些标的变成研究动作” | 从选股结果到观察池 ≤ 3 次点击；自选页可直接发起预警/回测 |

### 1.3 设计目标（按优先级）

1. **可解释**：每个空态、错误、禁用都有“为什么”和“下一步”，不只显示错误码。
2. **角色即视图**：同一页面按角色呈现不同能力，而不是“先给全量按钮再 403”。
3. **数据密度优先**：这是研究工具，表格与数字优先于装饰；颜色只用于表达涨跌/状态。
4. **操作可逆**：删除类操作有明确影响面说明；批量操作有结果汇总。
5. **移动可读**：小屏不做功能裁剪，宽表用横向滚动容器 + 折叠次要列。
6. **服务端一致**：界面文案与后端错误头（`X-Auth-Error`）一一对应，不吞错、不猜错。

### 2.3 现有全局能力

- **登录门禁**：`SM_AUTH_ENABLED`；关闭时所有接口开放，但账号页仍可用（`SessionGate` 只在
  `auth_enabled && !user` 时跳转）。
- **工作区隔离**：`SM_DATA_ISOLATION` 默认 `false`；开启后所有数据请求带 `X-Workspace-Id`，
  后端按 `owner/editor/viewer` 判定读写。
- **配置下发**：`GET /api/v1/auth/config` 返回 `auth_enabled / allow_register / wechat_enabled /
  wechat_mode / has_users / workspace_enabled / version`，前端据此决定入口显隐。
- **状态栏**：`frontend/src/StatusBar.tsx` 每 30s 轮询 `/system/status`，展示版本、日线行数、
  调度器、数据源熔断；后端不可达时降级为黄色横幅。
- **查询失效**：TanStack Query；切换工作区通过 `<Routes key={currentId}>` 整树重挂载。

### 2.4 现状问题清单（设计要解决的）

| # | 问题 | 影响 | 归属分册 |
|---|---|---|---|
| 1 | 登录/注册共用一个表单，字段随 Tab 增删，校验规则只在 placeholder 里 | 首次使用易错、错误不可解释 | AUTH |
| 2 | 登录失败直接展示后端中文 detail，缺少“账号被禁用/密码错误/注册关闭”的行动指引 | 用户不知道找谁 | AUTH |
| 3 | 微信三种模式（open/mp/mock）在 UI 上只有一句 mock 提示，取消/失败回流路径不可见 | 排障困难 | AUTH |
| 4 | 工作区页单列堆叠 1100+ 行，owner 的“配置”与成员的“查看”混在一起 | 找不到入口、误操作 | WORKSPACE |
| 5 | 危险操作分散（移除成员、转让、删除并清空）确认强度不一致 | 误删风险 | WORKSPACE |
| 6 | 自选没有独立页；多清单/备注能力无入口；Dashboard “管理”跳到行情页 | 能力闲置 | WATCHLIST |
| 7 | 自选与预警/回测之间没有交叉入口 | “观察池”链路断裂 | WATCHLIST |
| 8 | 选股结果无法批量加入自选 | 手工抄代码效率极低 | WATCHLIST |

> 说明：以上都是**交互层**问题，不是后端缺失。后端缺口集中在自选的“枚举清单 / 批量导入 /
> 批量删除 / 批量行情”，已在 [UI_WATCHLIST.md](UI_WATCHLIST.md) §5 给出契约。

## 3. 设计原则

1. **先解释，再操作。** 空态、权限不足、配额超限都给出“为什么 + 下一步按钮”；
   例如 viewer 看到的是“你在本工作区为查看者，写入需 owner 授权”，而不是灰掉的按钮群。
2. **一个任务一个主按钮。** 每个区块只保留一个 `.btn-primary`；危险操作永远不是主按钮。
3. **就地反馈。** 表单错误贴在字段下方；列表操作结果用页内 flash 区（现有 `flash()` 模式），
   不使用浏览器 `alert`（除不可逆确认可用 `window.confirm` 过渡）。
4. **角色决定视图，服务端决定真相。** 前端隐藏/禁用只减少误触；403/404/409 仍必须处理。
5. **数字优先、表格优先。** 同一屏内先给可比较的数值，再给解释文字；图表必须能被表格替代。
6. **不新增一级导航**（自选除外）。工作区、账号沿用顶部/用户菜单入口，避免导航膨胀。
7. **复用既有组件类。** 新界面只用 `index.css` 已定义的 `.card / .btn / .btn-primary / .input /
   .label / .th / .td / .badge / .table-wrap`，不引入第二套视觉语言。

**导航规则**

- 登录前（`/login`、`/auth/callback`）**不渲染**全局导航与状态栏，避免“未登录却能点页面”。

- 工作区切换器仅在工作区启用且已登录时出现；切换后整棵路由子树重挂载（数据自动重取）。
- 账号入口固定在右上角用户菜单；“工作区”页仍从切换器右侧“成员与设置”进入。

## 5. 视觉语言与设计 tokens

### 5.1 色板（全部来自 `frontend/src/index.css` 与 Tailwind 默认色）

| Token | 值 | 用途 |
|---|---|---|
| 页面背景 | `#0b1120`（body） | 全局底色，`color-scheme: dark` |
| 卡片背景 | `slate-900/60` + `border-slate-800` + `rounded-lg` | `.card` |
| 主色 | `sky-600`（hover `sky-500`） | 主按钮、选中导航、链接 |
| 正文 | `slate-100` / `slate-200` | 标题 / 表格值 |
| 次要文本 | `slate-400` / `slate-500` | 标签 / 说明 / 空态 |
| 分割线 | `slate-800` / `slate-800/50` | 卡片边框、表格行 |
| 上涨 | `#ef4444`（`--color-up`，红） | A 股口径：红涨 |
| 下跌 | `#22c55e`（`--color-down`，绿） | 绿跌 |
| 平盘 | `#94a3b8`（`--color-flat`） | 平盘/未知 |
| 成功 | `emerald-400 / emerald-900/50` | 状态 badge、成功提示 |
| 警告 | `amber-300 / amber-950/40` | 降级、只读、mock 提示 |
| 危险 | `red-300 / red-950/40` | 错误、禁用、危险操作 hover |
| 微信品牌 | `#07c160` | 仅微信登录按钮 |

**规则**

- 涨跌颜色**不得作为唯一信息载体**：数值始终带 `+/-` 符号，表格可加“↑/↓”文本。
- 图表配色：主序列 `#38bdf8`（sky-400）、次序列 `#f59e0b`（amber-500）、网格 `#1e293b`、
  轴标签 `#94a3b8`（与 `Workspace.tsx` 用量趋势图一致）。
- 不使用渐变、阴影堆叠；登录卡片可用 `shadow-2xl shadow-black/40`（现有实现）。

| 辅助说明 | `text-[11px]` / `text-xs text-slate-500` |
| 移动端输入框 | 强制 `font-size: 16px`（`index.css` 已内置，防 iOS 缩放） |

### 6.1 既有组件类（唯一允许的视觉基元）

|---|---|---|---|
| `.card` | `index.css` | 区块容器 | 所有页面区块必须用它，不自造边框 |
| `.btn` / `.btn-primary` | `index.css` | 次按钮 / 主按钮 | 每区块最多一个 primary |

### 6.2 需要统一的交互模式

**A. 表单页（登录、注册、账号、工作区配置）**

```text
标题
[字段标签]  [输入控件]            ← 必填 *；错误紧贴字段下方
[字段标签]  [输入控件]
[主按钮]  [次按钮]                ← 提交中按钮文案变“处理中…”并 disabled
页内提示区（成功/失败，aria-live="polite"）
```

- 前端先做与后端一致的即时校验（必填、长度、邮箱格式、两次密码一致），提交后以后端错误为准。
- 错误文案格式：`<做什么失败了>：<原因>。` 例如 `保存失败：邮箱已被使用。`
  后端 `detail` 已经可读时直接展示；不可读的错误码走 §6.4 映射表。

**B. 列表页（自选、成员、通道、用户）**

```text
┌ 区块标题 ───────────────────────── [主操作] [⋯ 更多] ┐
│ 筛选/搜索行（可选）                                   │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 表头（可排序列带 ▾）                              │ │
│ │ 行 …                                             │ │
│ └──────────────────────────────────────────────────┘ │
│ 空态 / 加载态 / 错误态（占位同一区域）                │
│ 底部：计数、分页或“加载更多”（如需要）                │
└──────────────────────────────────────────────────────┘
```

**C. 危险操作确认**

| 操作 | 确认方式 | 必须说明的影响面 |
|---|---|---|
| 移除成员 | `window.confirm`（P0）→ 自定义确认框（P1） | 该成员将失去本工作区读写权限 |
| 转让所有权 | 输入/选择新 owner + 二次确认 | 自己降为编辑者，不可撤销（可再转让） |
| 删除工作区 | 二次确认 + `purge` 复选 | 是否连同自选/规则/回测一起删除 |
| 批量删除自选 | 确认框列出条数 | 仅移出清单，不删行情数据 |
| 解绑微信 | 确认框 | 将无法再用该微信登录（仍有密码入口时说明） |

**D. 加载 / 空 / 错三态（所有数据区块必须实现）**

| 态 | 表现 | 文案示例 |
|---|---|---|
| 加载 | 区块内 `text-xs text-slate-500` “加载中…” 或骨架行 | 加载中… |
| 空 | 居中说明 + 一个下一步按钮/链接 | 自选为空，去行情页挑几只 → |
| 错 | 区块内黄色/红色说明 + 重试按钮；不阻塞页面其他区块 | 自选加载失败：网络不可达 [重试] |

**E. 角色/权限受限态**

- viewer：页面顶部 amber 提示条（现有 WorkspaceBar 已显示“只读”）；写操作按钮 `disabled`
  并带 `title` 说明；不隐藏只读内容。
- 非成员：后端统一 404，前端显示“工作区不存在或你无权访问”，不猜测存在性。
- 配额超限：表单提交后 409 → 页内提示“已达上限（N/M），请联系管理员调整 SM_WORKSPACE_MAX_*”。

### 6.3 文案风格

- 按钮：2–6 字动词短语（`保存`、`加入自选`、`立即扫描`、`重试`）。
- 提示：先说结果，再说原因/下一步（`已加入「核心组合」；其中 1 只已存在，已更新备注`）。
- 不使用感叹号；不使用“您”；日期统一 `YYYY-MM-DD`（`formatDateTime` 已有）。
- 免责声明不进入操作流，仅在 footer 与总览页保留。

### 6.4 错误码 → 文案映射（跨分册共用）

| 来源 | 标识 | 展示文案（示例） | 处理 |
|---|---|---|---|
| HTTP 401 | `bad_credentials` | 用户名或密码不正确 | 保留用户名，聚焦密码 |
| HTTP 403 | `read_only` | 你在本工作区为查看者，无法修改数据 | 禁用按钮 + 提示 owner |
| HTTP 403 | 注册关闭（现状无 code；建议补 `registration_disabled`【拟新增】） | 当前已关闭自助注册，请联系管理员开通账号 | 隐藏注册 Tab / 引导登录 |
| HTTP 404 | 工作区/资源不存在 | 工作区不存在或你无权访问 | 回到个人工作区 |
| HTTP 409 | `quota_exceeded` | 已达本工作区上限（N/M），请联系管理员 | 提示清理或联系 owner |
| HTTP 409 | 邮箱已使用 / 重名（现状无 code） | 该邮箱已被其他账号使用 | 字段级错误 |
| HTTP 422 | 校验失败 | 直接展示后端可读 detail | 字段级或表单顶部 |
| 网络/5xx | — | 无法连接后端，请稍后重试 | 保留输入，提供重试 |

> 具体 code 以各分册从代码中核实的结果为准（[UI_AUTH.md](UI_AUTH.md) §6.2 有完整清单）；
> 上表是统一呈现格式，不替代真实 code 清单。

## 7. 全局状态与开关矩阵

前端通过 `GET /api/v1/auth/config` 得到四个决定性开关（`auth_enabled`、`allow_register`、
`wechat_enabled/wechat_mode`、`workspace_enabled`），再叠加 `has_users`、登录态、角色、数据态。

| 维度 | 取值 | 界面影响 |
|---|---|---|
| 登录门禁 | `auth_enabled=false` | 不强制跳登录；登录页显示黄色说明；导航照常 |
| 自助注册 | `allow_register=false` | 登录页不显示注册 Tab；注册接口 403 |
| 微信登录 | `wechat_enabled=false` | 不显示微信按钮 |
| 微信模式 | `open` / `mp` / `mock` | `mock` 在按钮下显示模拟授权提示；`off` 等同禁用 |
| 初始账号 | `has_users=false` | 登录页提示“首个注册用户将成为管理员” |
| 工作区隔离 | `workspace_enabled=false` | 不显示切换器与工作区页入口；工作区页显示说明卡 |
| 登录态 | 匿名 / 已登录 | 决定用户菜单、`/account`、`/users` 可见性 |
| 平台角色 | `admin` / `user` | 决定 `/users` 与管理员总览 |
| 工作区角色 | `owner` / `editor` / `viewer` | 决定写操作显隐与禁用 |
| 数据态 | 已同步 / 未同步 / 过期 / 降级 | 显示数据日期、stale 提示、降级提示 |

**组合规则（不得只判断单一开关）**

```text
强制登录 = auth_enabled && !user
显示注册 = allow_register && !has_users ? 仍显示（首用户管理员） : allow_register
显示工作区 = workspace_enabled && user
可写 = !workspace_enabled || workspace.role !== "viewer"
管理员入口 = user.role === "admin" || (auth_enabled === false && !user)   # 现有 canManageUsers 语义
```

## 10. 跨文档统一约定

1. **名词**
   - “工作区”= Workspace（个人工作区也属于工作区，`kind=personal`）。
   - “自选清单”= 一个 `list_name`；“自选股”= 清单内一条 `watchlist_items` 记录。
   - “查看者/编辑者/所有者”= viewer/editor/owner，界面不出现英文角色名。
2. **工作区请求头**：所有数据请求由 `api.ts` 统一带 `X-Workspace-Id`，页面不手写该头。
3. **切换工作区**：不改 URL，清空查询缓存由路由 `key` 完成；页面不得缓存跨工作区数据。
4. **新增路由**：自选固定 `/watchlist`；其余不新增页面路由（弹层/抽屉不算路由）。
5. **接口缺口写法**：必须写清 method/path、请求体、成功/失败码、与现有约束（唯一键、配额、
   工作区归属）的关系，并注明是否破坏向后兼容。
6. **验收写法**：优先写“可观察行为 + 建议测试文件/用例名”，不写“实现 XXX 组件”。
7. **不引入新依赖**：不新增 UI 组件库、图表库、状态库；图标继续用内联 SVG 或文字符号。

## 14. 术语表

| 术语 | 含义 |
|---|---|
| 门禁 | `SM_AUTH_ENABLED=true` 时未登录用户被重定向到 `/login` |
| 个人工作区 | 每个账号自动拥有的 `kind=personal` 工作区，用于迁移/个人数据 |
| 共享工作区 | `kind=shared`，成员按角色共享数据 |
| 清单 | `watchlist_items.list_name`，同一工作区内名字唯一（按清单分组） |
| 观察池 | 由选股结果物化而来的自选清单，用于后续预警/回测 |
| 只读工作区 | 当前账号角色为 `viewer`，写操作被服务端拒绝（403 `read_only`） |
| 未同步 | 该标的没有本地日线，界面应提示“去设置页同步”，而不是显示 0 |
| stale | 最新数据日期落后于交易日历，需要提示数据时效 |
